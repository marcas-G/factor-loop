# 问题定义：因子库的知识资产化

> 状态：讨论稿 v1（2026-08-18）
> 用途：数据建模与工具设计的对齐基准，后续设计都应回到这里校验。

## 一句话问题

因子库目前是生产流水线的存档，不是研究决策的知识资产；它无法稳定回答三个问题：
下一步研究什么、新因子相对全库的边际贡献是多少、库能否组成低冗余可组合的因子集。

> 数据建模设计见 [data-model.md](./data-model.md)。

## 痛点

- 循环能稳定产出因子并入库，但库没有在减少重复劳动：高 ICIR 因子仍可能在 X 空间高度冗余。
- 单个因子看 ICIR 很高，但相对既有因子线性冗余，`res_IC` 接近零、`R2_X` 高，库没有在实验后把冗余判定真正收口。
- 研究建议（现 `iteration_suggestions`，旧 `iterations` 已退役为兼容视图）被打开却从不被接续，教训和失败原因没有被消费，知识没有复利。
- 行为检索基础设施（IC 行为向量、graph/rollup）覆盖不全，实验后的冗余判定无法可靠依赖。

## 期望状态

每轮研究都让库变得更会挑对象、避重复、补空白，并且能回答：

1. 下一步研究什么：由 coverage 空白、研究耗尽度、open iteration 共同驱动，而不是随机续跑。
2. 新因子对库的边际贡献：实验后通过行为检索（`behavior_edges` / `residual_strength`）和平台 restest 回答。
3. 库能否组成低冗余可组合的因子集：以 `res_IC`/`R2_X` 为标准沉淀正交资产，而不是堆积同族因子。

知识复利是核心：迭代建议被 `realized`，lesson 在评估与接续时被消费，失败方向不再重蹈。

## 两个相关性：必须区分基准空间

库里有两类“相关/冗余”，它们回答的是不同问题：

| 空间 | 基准 | 数据来源 | 回答的问题 |
|---|---|---|---|
| 本地迭代空间 | 我自己迭代的因子库（会增长、会变化） | `factor_ic_daily` / `factor_ic_vec` → `factor_ic_correlate`、`residual_ic_strength` | 新因子和我已经产出的因子是否重复？ |
| 平台参照空间 | 平台固定参照库（如 `qyshen/0727pass_v3`，AG/AU 72 因子） | 平台 Ridge-SVD restest → `R2_X` / `res_IC` | 新因子相对外部成熟因子库是否冗余？ |

关键含义：

- 同一个因子在两个空间里的结论可能不同：对本地库新颖，但已被外部库覆盖；反之亦然。
- 现有 `factors.latest_r2_x / latest_res_ic` 只来自平台参照空间；本地空间的值目前靠 `factor_ic_vec`，但覆盖只有 6/36。
- 建模时必须把“基准空间”做成显式维度，不能混在一个字段里；本地库还会随时间变化，因此还要记录基准快照。

**已定决策**：本地迭代空间的“相关性”定义为行为相关，即日级 IC 序列的 Pearson 同涨同跌
（`factor_ic_correlate` / `residual_ic_strength`）；公式/字段/算子结构相似只作 R3 查重辅助，
不作为本地冗余判据。

**已定决策（环节分工）**：实验前不做冗余检索，只做构造审查（因子写法、框架规范、算子借鉴与复用）；
冗余判定统一放在实验后（`check_done` → 行为检索 → assess），把口收紧在最终评估。

## 本地空间检索模型（已定）

检索按“场景”进行，场景 = `(factor, symbol, variant, y_horizon)`，其中 `variant` 即现有
`freq` 字段（平台参数化名，非时间频率）。检索链路：

```text
输入：目标场景 (factor, symbol, variant, y_horizon)
  → ① ANN 粗筛：250 维归一化 IC 向量近邻，限定同 symbol + 同 y_horizon
  → ② 精确复核：回 factor_ic_daily 用重叠日期算真实 Pearson
  → ③ 全库新颖性：residual_ic_strength 岭回归，相对 evaluated 基底
```

四条设计约定：

1. **检索永远限定场景内**：不跨 `symbol`、不跨 `y_horizon` 比较，因为跨场景的同涨同跌业务意义弱。
2. **两级判定**：ANN 只粗筛候选，进入决策的必须是精确 Pearson / residual strength。
3. **检索结果落库**：新增 `behavior_edges` 持久化 `(target, neighbor, scene, pearson, n_overlap, computed_at, base_snapshot)`，供 R1、看板、候选设计直接消费，不每次重算。
4. **进入行为空间的时机**：新因子在 `check_done` 前不做冗余检索，只做构造审查；`check_done` 后立即 `factor_ic_refresh`，才进入行为空间做冗余判定。

基底规则：本地空间只对照 `evaluated` 因子，排除 `dead_end`，避免死路因子累积污染冗余判定。

## 边界（本轮非目标）

- 不解决因子是否真实可交易、资金容量、成本后的 alpha；可交易性是组合层的后续问题。
- 不追求因子数量增长，不以“多产出”为成功。
- 不改变现有 cog/assess 研究主链协议，只补库的消费与反哺。
- 不设实验前冗余检索；实验前只做因子写法和算子借鉴的构造审查。
- 数据建模和工具设计是下游：先以本文为基准，再决定对象、关系和工具。

## 成功判据

1. 候选/写因子阶段做构造审查（因子写法、框架规范、算子借鉴/复用），不做冗余检索。
2. 每次 assess/persist 后，派生数据自动补齐：IC 向量、行为边、evidence rollup、research state、质量分。
3. open iteration 的 realized 比例大于 0，建议被真正接续而不是只被记录。
4. 新 pass 因子在两个基准空间（本地迭代库、平台参照库）的边际增量都可观测，且不持续下降、`R2_X` 不持续堆积。
5. 系统能回答“下一个最值得研究的对象是谁”，且理由可审计。
