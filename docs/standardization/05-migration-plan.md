# 05 · 迁移路线与验收（非破坏性）

## 阶段 P0 — 标准化基线（本 PR）

**交付**：AS-IS 清单、目标模块边界、版本化数据契约、示意样例、静态契约 CI。

**约束**：不移动核心代码；不改 `core/db/schema.sql`、`research-loop`、`auto-loops.sh`、MCP server、环境配置；不声称这些新类型已经接入生产。

**验收**：样例 JSON 均通过 schema，节点父子一致、细化理由存在、例子时序不泄漏、H0 存在；文档明确现有 API 与拟议 API 不同。

## 阶段 P1 — 稳定现有 Autoloop 再扩展

优先修复可靠性，而不是先并行扩大研究规模：

1. 用 run_id 固定归属及查询，修复 resume 路径的完成检测。
2. paused 与 done 分流；对所有终态做幂等 marker。
3. 统一 retry policy 和明确 stop reason，设计跨进程 lease/超时恢复。
4. 受控权限和资源预算；回归保留单车道现有功能。
5. 运行时契约测试与灾难注入（写 .h 后进程退出、工具失败、重复 resume）。
6. `run_store` 与 DB 的执行状态继续由已有工具维护，不能让新 Agent 直接写 JSON。

**验收**：固定 run_id 的新建/断点/暂停/失败各路径测试通过，原有 factor-driven 研究不退化。

## 阶段 P2 — TreEvo 最小研究树（先不回测）

**实施状态（2026-11-16）**：P2-a 独立 SQLite 树与现象候选适配已实现；P2-b 模型假设细化、第二轮批评、pending 审核队列与人工接受/拒绝已实现。均未接入现有自动因子循环，也未开展正式 LLM/市场实证对照。下列原始目标中，独立标注基准、语义质量验证、自动研究调度仍待完成。

1. 将一个宽泛 `ResearchTheme` 与 `Phenomenon` 输入构造成 `HypothesisNode`。
2. 使用五种 `refinement_type` 逐步细化，必须提交 `refinement_warrant` + `new_information`；保持无限深度**可选**，不强迫每层固定数目。
3. 对两条 competing hypotheses 生成能区分的预期观测；不可观测时设置 `blocked`，保留未解决节点。
4. 建立明确的研究树存储：typed edge、版本、幂等节点创建、无环、出处引用、历史快照。
5. 只在探索集上制作示例和小型人工标注测例；不将高收益当作假设树质量的评分。

**验收**：与无类型树/直接生成假设比较，人工核对逻辑连续性、细化信息增量、可观测性、捏造机制率和重复主张率。

## 阶段 P3 — 实验契约与已有平台连接

1. 建立 `ExperimentDesign -> investigation.Test Contract` 的显式 adapter；当前 contract 强制 H1/H2/H3/H0，缺项则拒绝或请求细化。
2. 将可实现的假设编译为 `FactorHandoff`，再映射到已有 `persist_candidates`；`factor_xname` 只有真实提交后写入。
3. 将统一实验记录与 `idea_id`、`node_id`、`factor_xname` 关联，不改原有事实表含义。
4. 让平台结果只通过独立 evidence refs 回填树节点，不让高 IC 自动升级假设的科学确定性。
5. 引入严格的探索/筛选/保留确认集及试验历史，考虑跨节点多重试验。

**验收**：一个示例主题经两次有效细化生成一个可执行因子，能反向定位所有父节点、对照条件和证据；无未来数据泄漏。

## 阶段 P4 — 多轮机制研究与比较

- 与现有 Factor 驱动单 Agent、主题直接生成、线性细化、无类型树作同预算对照。
- 研究质量指标：有效细化率、非同义机制增量、竞争解释可区分性、可观测性、证据状态校准、树分叉覆盖。
- 工程指标：任务恢复成功率、重复实验率、状态一致性、成本。
- 预测效用指标：只有在**独立确认集**上判断；固定评估协议，记录所有尝试，不以训练过程高 IC 替代最终效果。

## 不在本 RFC 范围

- 不实现 TreEvo 的完整 Agent 调度器。
- 不重写现有因子评估阈值、算子归约或数据库迁移。
- 不把所有已有概念或技术模块复制到通用 Agent Marketplace。
- 不把因子血缘树转换为科学解释树。
- 不做无法核验的定量效益承诺。

## 完成定义

`architecture standardized` = 文档与示例契约已审核、验证器通过。
`integration complete` = P1–P3 代码变更及回归测试通过。
`scientifically supported` = P4 独立评估支持增益。

上述三个里程碑不可混称。
